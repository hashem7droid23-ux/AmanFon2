# تجهيز ونشر النسخة الرسمية من أمان فون (الإصدار 2.0)

## الحالة الراهنة وما تم إنجازه في المستودع

1. **إعدادات البناء والتوقيع:**
   - تم تحديث `versionCode` إلى `11` و`versionName` إلى `2.0`.
   - تم ضبط إعدادات التوقيع في `app/build.gradle.kts` لتقبل بيانات توقيع الإنتاج بأمان عبر متغيرات البيئة.
   - تم تصحيح إعدادات فحص Lint لمنع التوقف غير المبرر على تنبيهات Activity Result.
2. **سير العمل والأتمتة في GitHub Actions:**
   - تم إنشاء سير عمل النشر الرسمي: `.github/workflows/production-release.yml`، ويتضمن:
     * استرجاع المفتاح من أسرار GitHub Secrets إلى مسار مؤقت محمي.
     * التحقق من مطابقة بصمة الشهادة `RELEASE_CERT_SHA256` قبل البدء في البناء.
     * تشغيل الاختبارات وبناء نسخة Release مصغّرة ومشفرة (R8/Proguard) وغير قابلة للتصحيح (`debuggable = false`).
     * فحص وتأكيد التوقيع الرقمي عبر `apksigner` ومطابقة الحزمة `com.aistudio.lostphone.ymndx`.
     * إنشاء الأصول الرسمية: `AmanPhone.apk` و`SHA256SUMS.txt`.
     * تحديث صفحة الإصدار `v1.0-apk` تلقائيًا وقراءة الوصف من ملف `RELEASE_NOTES.md` المخصص للمستخدمين.
   - تم تعديل سير عمل النسخة التجريبية `.github/workflows/build-apk.yml` بحيث:
     * يقتصر على بناء نسخة الاختبار ورفعها كـ Artifact.
     * تم حذف خطوة النشر إلى GitHub Releases منه نهائيًا لمنع أي بناء تجريبي قديم من استبدال النسخة الرسمية أو وصفها.
     * تم استثناء ملفات التوثيق و`update.json` من مشغلات البناء لمنع حلقات التكرار غير الضرورية.
3. **ملاحظات الإصدار وقواعد التحديث:**
   - تم إعداد `RELEASE_NOTES.md` بوصف عربي مباشر يركز على المميزات التي تهم المستخدم مع إزالة أي مبالغات.
   - تم تحديث `CHANGELOG.md` وتوثيق الإصدار 2.0.
   - تم إعداد قسم `production` في `update.json` ليتوافق مع الإصدار 2.0.

## الخطوات المطلوبة من طرفك (لحفظ الأمان والخصوصية)

نظراً لأن بيئة المساعد السحابية لا تملك صلاحيات إدارة GitHub Secrets أو تسجيل الشهادات في لوحة تحكم Firebase، وحفاظاً على سرية مفتاح التوقيع وكلمة مروره وعدم كشفهما في سجلات المحادثة أو فقدانهما عند انتهاء الجلسة، اتبع الآتي:

### 1. توليد المفتاح الخاص وحفظ نسخته الاحتياطية على جهازك
على جهازك الموثوق (Linux أو macOS)، افتح الطرفية ونفّذ:
```bash
bash ci/setup-production-key.sh
```
- اختر كلمة مرور قوية للمستودع (16 خانة فأكثر).
- سيقوم السكربت بحفظ المفتاح محلياً في مجلد خاص خارج المستودع (`~/.aman-phone-signing/`).
- **هام جداً:** احتفظ بنسخة احتياطية آمنة ومشفرة من ملف `aman-phone-production.p12` وكلمة المرور في وسيلة تخزين آمنة خاصة بك؛ لا تفقد هذا المفتاح لأنه هو المفتاح الوحيد لتوقيع جميع تحديثات التطبيق المستقبلية.

### 2. تسجيل بصمات الشهادة في Firebase وGoogle
سيطبع السكربت بصمتي الشهادة العامة (SHA-1 و SHA-256).
1. افتح [Firebase Console](https://console.firebase.google.com/) للمشروع `gen-lang-client-0428838696`.
2. ادخل إلى إعدادات المشروع (Project Settings) > تطبيق Android ذي الحزمة `com.aistudio.lostphone.ymndx`.
3. اضغط على **Add fingerprint** وأضف بصمتي SHA-1 و SHA-256 للشهادة الجديدة (مع الإبقاء على البصمة السابقة إن رغبت بدعم الأجهزة التجريبية الحالية).
4. تأكد من أن شاشة موافقة OAuth في Google Cloud Console بحالة مقبولة للمشروع، وأن عميل Android يتطابق مع البصمة الجديدة.

### 3. حفظ أسرار التوقيع في GitHub Secrets
في مستودع المشروع على GitHub (`hashem7droid23-ux/AmanFon2`):
اذهب إلى: **Settings** > **Secrets and variables** > **Actions** > **New repository secret**
وأضف القيم التالية (التي أظهرها لك سكربت `setup-production-key.sh` أو رفعها تلقائيًا عبر `gh`):
- `RELEASE_KEYSTORE_BASE64`: محتوى ملف المفتاح مرمزاً بـ Base64.
- `STORE_PASSWORD`: كلمة مرور Keystore.
- `KEY_PASSWORD`: كلمة مرور المفتاح.
- `KEY_ALIAS`: `amanphone`
- `RELEASE_CERT_SHA256`: بصمة شهادة التوقيع بصيغة 64 حرف Hex (بدون نقاط أو فواصل).

*(ملاحظة: إذا أنشأت بيئة `production` في GitHub Settings > Environments، يمكنك وضع الأسرار ضمنها أيضاً).*

### 4. تشغيل بناء ونشر النسخة الرسمية
من تبويب **Actions** في مستودع GitHub:
1. اختر سير العمل: **Build and Publish Production Release**.
2. اضغط على **Run workflow** على فرع `main`.
3. يمكنك تشغيل البناء أولاً مع بقاء خيار `publish_to_release` بقيمته الافتراضية (`false`) لإنشاء نسخة مرشحة واختبارها محلياً كـ Artifact.
4. عند الرغبة بالنشر الرسمي للعامة، فعّل خيار `publish_to_release: true`؛ سيقوم السير تلقائياً بما يلي:
   - تشغيل اختبارات `testReleaseUnitTest` و `lintRelease` وتجميع `assembleRelease`.
   - استخراج `versionCode` و `versionName` الفعليين من ملف APK المبني.
   - التحقق من عدم تراجع رقم الإصدار عن آخر إصدار منشور.
   - فحص وتأكيد التوقيع الرسمي بواسطة `apksigner`.
   - رفع الملف `AmanPhone.apk` وملف `SHA256SUMS.txt` وتحديث وصف الإصدار تلقائياً من `RELEASE_NOTES.md`.
   - التحقق الفوري من حالة وتطابق الأصل المرفوع عبر واجهة GitHub Releases.
   - تحديث `update.json` تلقائياً ببيانات التوقيع وحجم وبصمة الملف وتفعيل إشعار التحديث (`enabled: true`) ودفعه إلى `main` مباشرة دون force push.
