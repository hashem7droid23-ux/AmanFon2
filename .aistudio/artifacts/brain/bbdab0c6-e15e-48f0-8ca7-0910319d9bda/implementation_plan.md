# أمان فون (Aman Phone) — خطة تجهيز وإصدار النسخة الرسمية 2.1 للنشر العام

تهدف هذه الخطة إلى ترقية تطبيق "أمان فون" إلى الإصدار الرسمي **2.1 (رقم البناء 12)**، وتوليد مفتاح توقيع الإنتاج الرسمي مع استخراج بصماته لتسجيلها في Firebase وGitHub Secrets، والتحقق الكامل من نجاح بناء وتوقيع نسخة `Release` لتكون جاهزة للنشر العام بضغطة واحدة عبر GitHub Actions.

### User Review & Critical Decisions

> [!IMPORTANT]
> تم إعداد هذه الخطة بناءً على اختياراتك المؤكدة لإنتاج النسخة الرسمية للنشر العام:

- **القرار المؤكد 1 (المسار المعتمد للنشر):** تجهيز المشروع بالكامل للنشر الرسمي الآلي عبر سير عمل GitHub Actions (`Build and Publish Production Release`) الذي يرفع ملف `AmanPhone.apk` إلى الإصدار `v1.0-apk` ويفعّل إشعار التحديث التلقائي.
- **القرار المؤكد 2 (ترقية رقم الإصدار):** رفع رقم الإصدار في إعدادات التطبيق إلى `versionCode = 12` و`versionName = "2.1"`، وتحديث ملاحظات الإصدار وسجل التغييرات لتعكس ميزات التحديث المباشر داخل التطبيق ومزامنة التنبيهات السحابية.
- **القرار المؤكد 3 (توليد مفتاح التوقيع واستخراج البصمات):** توليد مفتاح توقيع إنتاج قياسي (`PKCS12`، خوارزمية `RSA 3072-bit`، الاسم المستعار `amanphone`) في مجلد مؤقت معزول تماماً عن Git، واستخراج بصمتي `SHA-1` و`SHA-256` لإضافتهما في Firebase Console، وتجهيز القيم الخمس المطلوبة لإضافتها في GitHub Secrets.

### 1. Overview & Core Concept

- **What It Does:** يجهز الإصدار الرسمي **2.1** من تطبيق "أمان فون" للنشر العام بتوقيع رقمي رسمي ثابت، مع التحقق المسبق من اجتياز جميع اختبارات الإنتاج وضغط الكود عبر R8/ProGuard.
- **Target Audience / Persona:** عموم المستخدمين وأصحاب الهواتف المفقودة وفنيو الهواتف في اليمن الذين سيحملون النسخة الرسمية النهائية `AmanPhone.apk`.
- **Key Value:** إصدار رسمي موقّع وموثوق، يدعم التحديث الداخلي المباشر للإصدارات القادمة دون الحاجة لحذف التطبيق، ومتوافق مع مصادقة Google السحابية.

---

### 2. User Experience & Visual Design

- **Key User Flows:**
  1. **تدفق التحميل والتثبيت للمستخدم النهائي:** يحمّل المستخدم ملف `AmanPhone.apk` (الإصدار 2.1) من صفحة الإصدار الرسمي، ويثبته على جهازه ليحصل على كافة الميزات (فحص IMEI، البلاغات المصورة، التنبيهات السحابية المتزامنة، والتحديث الذاتي داخل التطبيق).
  2. **تدفق الترقية التلقائية مستقبلاً:** بفضل توحيد مفتاح توقيع الإنتاج وتفعيل `update.json` تلقائياً عند النشر، سيتلقى مستخدمو هذه النسخة إشعاراً داخل التطبيق عند توفر أي إصدار مستقبلي (مثل 2.2) مع تحميل وتثبيت مباشر من داخل التطبيق.
- **Visual Identity & Theme:**
  - *Aesthetic Direction:* واجهة عربية كاملة (RTL) بالهوية الداكنة الرسمية وألوان الذهبي اليمني والأحمر التحذيري.
  - *Release Presentation:* عرض بطاقة إصدار احترافية ومنسقة باللغة العربية في صفحة GitHub Releases توضح مميزات الإصدار 2.1 ورابط التحميل المباشر وبصمة التحقق `SHA-256`.

### 3. Key Product Decisions & Trade-Offs

- **Decision 1: توليد مفتاح الإنتاج في مسار معزول خارج المستودع (`/tmp`)**
  - *Chosen Approach:* إنشاء ملف مفتاح التوقيع في مسار مؤقت خارج مجلد المشروع وعدم إضافته نهائياً إلى سجل Git، مع التحقق من بناء النسخة الرسمية وتوقيعها به ثم حذف الملف المؤقت بعد تسليمك بيانات الاعتماد والبصمات لحفظها في GitHub Secrets ونسختك الاحتياطية.
  - *Why:* يضمن بقاء مفتاح التوقيع سرياً 100% ويمنع تسربه في الكود المصدري العام للمستودع.
  - *Alternatives Considered:* حفظ ملف المفتاح داخل مجلد المشروع، وقد استُبعد تماماً لمخالفته قواعد الأمان.
- **Decision 2: رفع `versionCode` إلى `12` و`versionName` إلى `"2.1"`**
  - *Chosen Approach:* تحديث إعدادات البناء وملاحظات الإصدار إلى `2.1 (12)` وضبط قناة `debug` في `update.json` إلى `13` وإبقاء قناة `production` على `enabled: false` في الكود المصدري حتى يفعّلها سير العمل تلقائياً عند النشر.
  - *Why:* يضمن توافق فحوصات عدم تراجع رقم الإصدار في سير عمل GitHub Actions عند إطلاق النشر الرسمي.

### 4. Technical Architecture & Data Strategy *(Technical Reference)*

- **Architecture & Release Pipeline Diagram:**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    1. Version & Metadata Preparation                    │
│  ┌──────────────────────┐  ┌──────────────────────┐  ┌───────────────┐  │
│  │ versionCode = 12     │  │ RELEASE_NOTES.md 2.1 │  │ update.json   │  │
│  │ versionName = "2.1"  │  │ & CHANGELOG.md 2.1   │  │ Ready State   │  │
│  └──────────┬───────────┘  └──────────┬───────────┘  └───────┬───────┘  │
└─────────────┼─────────────────────────┼──────────────────────┼──────────┘
              └─────────────────────────┼──────────────────────┘
                                        ▼
┌─────────────────────────────────────────────────────────────────────────┐
│               2. Isolated Key Generation & Pre-Flight Check             │
│  ┌─────────────────────────────────┐  ┌──────────────────────────────┐  │
│  │ Generate PKCS12 Key (RSA 3072)  ├─►│ Extract SHA-1 & SHA-256      │  │
│  │ in isolated /tmp directory      │  │ + Base64 for GitHub Secrets  │  │
│  └────────────────┬────────────────┘  └──────────────┬───────────────┘  │
│                   ▼                                  ▼                  │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ Verify: testReleaseUnitTest + lintRelease + assembleRelease       │  │
│  │ Verify APK signature via apksigner & clean up temporary key file  │  │
│  └────────────────────────────────┬──────────────────────────────────┘  │
└───────────────────────────────────┼─────────────────────────────────────┘
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│             3. GitHub Actions Production Release Execution              │
│   Push to main ──► Add Secrets & Firebase SHA ──► Run Workflow (true)   │
│        ──► Publishes AmanPhone.apk (v1.0-apk) & Activates update.json   │
└─────────────────────────────────────────────────────────────────────────┘
```

- **Data Model & State:**
  - **بيانات الإصدار (`2.1` / `12`):** تحديث رقم الإصدار في إعدادات التطبيق، وتحديث نص ملاحظات الإصدار الرسمي ليشمل ميزة التحديث المباشر داخل التطبيق ومزامنة التنبيهات السحابية.
  - **بيانات التوقيع الخمسة لـ GitHub Secrets:**
    - `RELEASE_KEYSTORE_BASE64`: النص المرمز بـ Base64 لملف المفتاح.
    - `STORE_PASSWORD` و`KEY_PASSWORD`: كلمة المرور القوية المولدة للمفتاح.
    - `KEY_ALIAS`: `amanphone`.
    - `RELEASE_CERT_SHA256`: بصمة الشهادة المكونة من 64 محرفاً سداسياً عشرياً للمطابقة الصارمة في سير العمل.
- **Interactive Component & State Mapping:**
  - تحديث ملفات الإصدار (`app/build.gradle.kts`، `RELEASE_NOTES.md`، `CHANGELOG.md`، `update.json`).
  - توليد المفتاح في `/tmp`، واختبار بناء `assembleRelease` الفعلي للتحقق من خلو البناء الرسمي من أي أخطاء R8/ProGuard، ثم حذف المفتاح المؤقت وتقديم جدول القيم الجاهزة لإضافتها في GitHub Secrets وFirebase Console.
