## فكرة التطبيق

أمان فون يساعد أصحاب الهواتف ومحلات البيع والصيانة على مراجعة بلاغات السرقة والفقدان قبل التعامل مع جهاز. يجمع بيانات البلاغ وصور الهاتف ووسائل التواصل في مكان واحد، ويتيح البحث باستخدام رقم IMEI.

> **قبل الشراء:** عدم وجود بلاغ لا يثبت ملكية الهاتف ولا يضمن أنه غير مسروق. طابق الرقم مع الجهاز والعلبة والفاتورة، واطلب إثبات الملكية.

## ما يمكنك فعله

| الخدمة | التفاصيل |
| :--- | :--- |
| **فحص الجهاز** | البحث برقم IMEI الأول أو الثاني عن بلاغات السرقة والفقدان النشطة. |
| **تسجيل بلاغ** | إضافة الموديل واللون ومكان الحادثة وبيانات التواصل والمكافأة الاختيارية. |
| **صور وأرقام الجهاز** | إرفاق حتى ثلاث صور، وإدخال الرقم التسلسلي أو مسح باركود IMEI وS/N. |
| **متابعة البلاغ** | توثيق استرجاع الهاتف أو حذف البلاغ وفق صلاحيات الحساب، بعد تأكيد الخادم. |
| **إدارة المحتوى** | أدوات للمشرفين للحظر والإخفاء والتثبيت والإعلانات وإدارة الفريق. |
| **الدخول والمزامنة** | Google أو البريد أو الهاتف بحسب إعدادات Firebase، مع حفظ نسخة محلية للعرض. |

## تحميل التطبيق

**[افتح صفحة التحميل](https://github.com/hashem7droid23-ux/AmanFon2/releases/tag/v1.0-apk)** واختر `AmanPhone-debug.apk` من قسم **Assets**.

النسخة المتاحة للاختبار وليست إصدار إنتاج. يُستبدل ملف APK بعد نجاح البناء والاختبارات على `main`؛ إذا فشل آخر بناء فقد يبقى الملف السابق. يمكنك مراجعة النتيجة في [GitHub Actions](https://github.com/hashem7droid23-ux/AmanFon2/actions).

## الجديد في 1.8

**مزامنة أدق.** معرفات سحابية ثابتة للبلاغات، مع تحديث البلاغ الموجود بدل تكراره، وتأكيد النشر والحذف والاسترجاع من الخادم قبل إعلان النجاح.

**نتائج فحص أوضح.** البحث في الخادم بدل الاكتفاء ببيانات الجهاز، وإظهار «الفحص غير مكتمل» عند تعذر الاتصال. عدم العثور على بلاغ نشط لا يُعرض كضمان لسلامة الهاتف.

**تحسين الأرقام والصور.** دعم الأرقام العربية والفارسية، والتحقق من طول IMEI عند 15 رقمًا، وربط الصور ببلاغ يملكه المستخدم مع ضبط حجمها والاحتفاظ بالصور المحلية غير المؤكد رفعها.

**بيانات واختبارات.** إيقاف إضافة البلاغات الوهمية، وإخفاء عينات البداية القديمة المعروفة، وترقية Room دون إسقاط الجداول، وإضافة اختبارات للتحقق من الأرقام والصلاحيات وهوية البلاغ والترقية.

## ملاحظات مهمة

- أمان فون يعرض البلاغات المسجلة فيه؛ ليس سجلًا حكوميًا ولا أداة لتتبع موقع الهاتف.
- الفحص والنشر وتأكيد الحذف أو الاسترجاع تحتاج إلى تسجيل الدخول والإنترنت. البيانات المحلية قد لا تكون محدثة.
- الماسح يقرأ **الباركود**، وليس النص المطبوع مباشرة، ويعتمد على خدمات Google Play.
- وصول التنبيهات يعتمد على الاتصال والمزامنة وإعدادات الجهاز، ولا يُضمن وصولها إلى جميع المستخدمين.
- نجاح اختبارات الكود لا يغني عن تجربة التطبيق على جهازين وحسابين مختلفين.

## للمطورين

المشروع مبني باستخدام **Kotlin** و**Jetpack Compose** للواجهة، و**Room** للتخزين المحلي، و**Firebase Authentication** و**Cloud Firestore** للمصادقة والبيانات. يتضمن أيضًا Firebase Cloud Messaging وGoogle Code Scanner.

<details>
<summary><strong>البناء المحلي والاختبارات</strong></summary>

<br>

تحتاج إلى JDK 17، وAndroid SDK المناسب لإعدادات المشروع، وملف `app/google-services.json`، وإعداد مفتاح توقيع النسخة المستهدفة.

</div>

```bash
chmod +x gradlew
./gradlew assembleDebug
```

<div dir="rtl">

الملف الناتج:

</div>

```text
app/build/outputs/apk/debug/app-debug.apk
```

<div dir="rtl">

بناء Debug يشغّل اختبارات الوحدة عبر مهمة ختامية. لتشغيل الاختبارات وAndroid Lint أيضًا:

</div>

```bash
bash ci/check.sh
```

<div dir="rtl">

</details>

<details>
<summary><strong>إعداد Firebase والتوقيع والمزامنة</strong></summary>

<br>

قواعد الوصول في `firestore.rules`. تعديل الملف في GitHub لا ينشره تلقائيًا إلى Firebase؛ يجب نشره إلى قاعدة البيانات المستخدمة في التطبيق. راجع [ملاحظات تجهيز الإصدار](ci/RELEASE_READINESS.md) للخطوات والقيود.

لا تضع مفتاح توقيع الإنتاج أو كلمات مروره في المستودع. تغيير توقيع APK قد يمنع تحديث النسخة المثبتة ويتطلب تحديث البصمات في Firebase وإعدادات Google.

عند استخدام AI Studio، نفّذ **Pull changes** قبل أي **Push**، وتأكد من بقاء ملف المفتاح الحالي دون تغيير. هذه خطوة احترازية وليست حماية تلقائية من الحذف.
