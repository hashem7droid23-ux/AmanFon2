# أمان فون | Aman Phone

تطبيق أندرويد لتسجيل بلاغات الهواتف المسروقة والمفقودة والمعثور عليها في اليمن، والبحث عنها باستخدام رقم IMEI. يساعد أصحاب الهواتف ومحلات البيع والصيانة على مراجعة البلاغات قبل التعامل مع جهاز.

## ما يقدمه التطبيق

- تسجيل بلاغ يتضمن بيانات الجهاز، مكان الحادثة ووسائل التواصل مع صاحب البلاغ.
- البحث برقم IMEI عن بلاغات السرقة والفقدان النشطة في قاعدة أمان فون.
- إرفاق صور الجهاز، وإدخال الرقم التسلسلي أو مسح باركود IMEI وS/N.
- تسجيل الدخول بحساب Google أو البريد الإلكتروني أو رقم الهاتف، بحسب إعدادات Firebase المفعّلة.
- إدارة البلاغات وتوثيق استرجاع الأجهزة، مع أدوات للمشرفين للحظر والإخفاء والتثبيت والإعلانات.
- حفظ نسخة محلية من البيانات لعرضها، ومزامنة البلاغات مع Cloud Firestore عند تسجيل الدخول.

## حدود الاستخدام

أمان فون يعرض البلاغات المسجلة فيه؛ ليس سجلًا حكوميًا ولا وسيلة لتتبع موقع الهاتف. عدم وجود بلاغ لا يثبت ملكية الجهاز ولا يضمن أنه غير مسروق. طابق IMEI مع الجهاز والعلبة والفاتورة، واطلب إثبات الملكية قبل الشراء.

فحص IMEI والنشر وتأكيد الحذف أو الاسترجاع تحتاج إلى تسجيل الدخول واتصال بالإنترنت. عرض بيانات محفوظة محليًا لا يعني أنها أحدث نسخة على الخادم. مسح الأرقام بالكاميرا يقرأ الباركود، وليس النص المطبوع مباشرة. وصول التنبيهات يعتمد على الاتصال والمزامنة وإعدادات الجهاز، ولا يوجد ضمان لوصولها إلى جميع المستخدمين.

## التحميل

يمكن تنزيل ملف APK من [صفحة الإصدارات](https://github.com/hashem7droid23-ux/AmanFon2/releases/tag/v1.0-apk).

الملف المنشور حاليًا هو `AmanPhone-debug.apk`، نسخة اختبار وليست إصدار إنتاج. يُحدّث الملف بعد نجاح البناء والاختبارات على الفرع `main`؛ قد تظل نسخة سابقة متاحة إذا فشل آخر بناء. راجع [GitHub Actions](https://github.com/hashem7droid23-ux/AmanFon2/actions) للتأكد من النتيجة.

## الجديد في الإصدار 1.8

- ربط البلاغات بمعرفات سحابية ثابتة لمنع تكرارها أثناء المزامنة.
- تأكيد النشر والحذف وتغيير حالة الاسترجاع من الخادم قبل إعلان نجاح العملية.
- فحص IMEI من الخادم، وإظهار حالة عدم اكتمال الفحص عند تعذر الاتصال بدل إعطاء نتيجة مطمئنة.
- استبدال عبارة «الجهاز سليم» بنتيجة توضح عدم وجود بلاغ نشط، مع التنبيه إلى حدود الفحص.
- دعم الأرقام العربية والفارسية، واشتراط 15 رقمًا لـ IMEI.
- إيقاف إضافة البلاغات الوهمية تلقائيًا، وإخفاء العينات القديمة المعروفة.
- ترقية قاعدة Room دون إسقاط الجداول، وإضافة اختبارات للترقية وهوية البلاغ والتحقق من IMEI والصلاحيات.
- ربط الصور ببلاغ يملكه المستخدم، وضبط حجمها، والإبقاء على الصور المحلية إذا لم يكتمل رفعها.

تفاصيل الإصدارات السابقة في [سجل التغييرات](CHANGELOG.md). يُحدّث هذا القسم والسجل مع كل إصدار، مع الفصل بين التغييرات المنفذة وما يحتاج إلى إعداد أو نشر خارجي.

## التقنيات

Kotlin، Jetpack Compose، Room، Firebase Authentication، Cloud Firestore، Firebase Cloud Messaging، وGoogle Code Scanner.

## البناء المحلي

تحتاج إلى JDK 17 وAndroid SDK المناسب لإعدادات المشروع، وملف `app/google-services.json` الخاص بمشروع Firebase، وإعداد مفتاح التوقيع الذي تستخدمه النسخة المستهدفة. لا تضع مفاتيح توقيع الإنتاج أو كلمات مرورها في المستودع.

```bash
chmod +x gradlew
./gradlew assembleDebug
```

الملف الناتج:

```text
app/build/outputs/apk/debug/app-debug.apk
```

بناء نسخة Debug يشغّل اختبارات الوحدة عبر مهمة ختامية. لتشغيل الاختبارات وفحص Android Lint أيضًا:

```bash
bash ci/check.sh
```

نجاح الاختبارات لا يغني عن تجربة النشر والصور والحذف والاسترجاع على جهازين وحسابين مختلفين.

## Firebase والتوقيع

قواعد الوصول محفوظة في `firestore.rules`. تعديل الملف في GitHub لا ينشره تلقائيًا إلى Firebase؛ يجب نشره إلى قاعدة البيانات المستخدمة في التطبيق. توجد خطوات التحقق والنشر في [ملاحظات تجهيز الإصدار](ci/RELEASE_READINESS.md).

تغيير مفتاح توقيع APK قد يمنع تحديث النسخة المثبتة ويحتاج إلى تحديث بصمات التطبيق في Firebase وإعدادات Google. عند المزامنة من AI Studio، اسحب تغييرات GitHub باستخدام **Pull changes** قبل أي **Push**، وتأكد من بقاء ملف المفتاح الحالي دون تغيير. هذه خطوة احترازية وليست حماية تلقائية من حذفه.
